EV Yatra

In development
Screenshots coming soon

Problem

Running an electric-scooter rental operation needs more than a booking form — it needs one system that serves customers, hub staff, and admins with very different jobs to do.

Solution

A traditional server-rendered Flask app with three separate, session-scoped panels: Customer, Employee, and Admin — each with its own login, its own blueprint, and its own set of pages.

Key features

Full booking → payment → rental lifecycle with coupons; an employee workflow (verify → handover → return) scoped to the employee's assigned hub, with maintenance requests raised automatically on damage; an admin panel covering scooters, hubs, employees, customers, bookings, payments, maintenance, charging, reports, and audit logs.

My contribution

Sole builder — schema design, all three Flask blueprints, every Jinja template, and the CSS/JS, from database to deployed UI.

Current status

In active development — customer, employee, and admin panels are built out across 15 tables, with core booking, handover, and admin workflows in place.
